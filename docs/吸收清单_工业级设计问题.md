# 吸收清单：从工业级实践带走的设计问题

边界声明（先说清楚再列清单）：从工业级多因子平台的**使用经验**里，合法
带走的是"哪些问题值得解决"的判断——这些问题与解法范式同样出现在 qlib、
alphalens、Barra 白皮书、AFML 等公开生态中，属于行业共识；下表每一行的
**实现**均为本仓原创，不含任何机构的私有代码、命名、格式或常数。

| 行业通行概念 | 它解决什么问题 | Spencer 的原创实现 | 状态 |
|---|---|---|---|
| 统一验证契约（入库门禁） | 没有统一尺子时，因子各自"自证优秀"，池子慢慢烂掉 | `factor/verify.py` 七关 admission_check（末端/覆盖/方向/逐年/NW-t/换手/查重），fail-warn-pass 三级判决 | ✅ |
| 因子登记元信息 | 因子没有户口：作者、数据依赖、有效起始日无人知晓 | `@factor(name, author=…, tags=…, valid_from=…)` + get_meta，valid_from 联动验证契约 | ✅ |
| 数据源有效起始日 | 财报/新数据源类因子在覆盖起点前的值是幻觉 | 元信息 valid_from + 契约内起始日裁剪 | ✅（按因子声明） |
| 多档中性化读数 | 单一口径看不出因子有多少收益是风格搭便车 | 三档 @raw/@size_neut/@full_neut，因子与标签两侧残差化，同函数同参数 | ✅ |
| 风险模型 Σ=BFB′+diag(spec²) | 组合构造需要前瞻协方差而非样本协方差 | `risk/covariance.py`：逐日截面回归因子收益 + EWMA F + EWMA 特异，PIT 滞后记账（测试钉死） | ✅ |
| 白箱组合优化 | 黑盒求解器出问题无从审计 | `strategy/optimizer.py` FISTA+截断单纯形投影+暴露带罚项，KKT 残差、λ→∞ 恒等式当场检验 | ✅ |
| 末端对齐纪律 | 数据更新因子不更新（或反之）的静默腐烂 | 缓存双判据（源码+数据形状指纹 / 末端对齐），出厂 assert | ✅ |
| 实验台账与 N 计数 | 试验次数不可考 → 多重检验校正无从谈起 | append-only ledger + DSR/PBO 直接从台账读 N | ✅ |
| 口径手册（数字带出处） | 口径散落，跨口径数字并排下错结论 | 每个模块 docstring 写死口径与已知近似；报告口径声明段强制 | ✅（体例） |
| 数据清册（catalog） | 有哪些表、覆盖到哪、末端在哪，无人说得清 | —— | 路线图 |
| 每晚增量调度 | 研究数据要天天新鲜，人肉拉数不可持续 | —— | 路线图 |
| 服务器侧不可绕过的发射台账 | 单机 append-only 台账在多机/多人下可被绕过 | 单机版已有；多机版需要执行侧钩子 | 路线图 |

一句话总结方法论：**复刻问题，不复刻解法**。问题清单是从业经验（属于
人），解法范式是公开知识（属于行业），实现是原创劳动（属于本仓）。
